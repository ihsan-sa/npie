## 2026-10-15 run 1

Did: #19 is still blocked, and it was the only open goal, so I looked for a gap under a standing goal. Every run on record had one. `npie_run.py` writes the report only when `advance` returns. Three ways out skipped that. (1) `--fault rail:+5V=abc` passed `create`'s check, made a run dir, then crashed in `SimBoard` with a ValueError the CLI doesn't catch. (2) A bench that failed to build did the same, because `npie_run.py` opened it outside `advance`'s try. (3) Ctrl-C is a `KeyboardInterrupt`, not an `Exception`, so it went past the abort. The run was left `running` with no report and, on a real bench, the supply still on. I filed "No run is left without its report" and did it in one step. `create` now refuses a rail fault with no volts. `advance` opens the bench inside its try. An interrupt aborts the run ("interrupted"), turns the supply off and saves the run, then re-raises. `npie_run.py` catches that, writes the report and exits 130. `tests/test_npie_run_orphans.py` covers each case plus resume. A fixture teardown fails if any run dir is left `running` or without `report.tex`. `make check`: 117 passed, 9 skipped. With the interrupt handler removed, both Ctrl-C tests fail. The goal is closed as done in this PR. I also added the Closed line for #42 and pointed that goal at #42.
Decided: Ctrl-C ends the run as `aborted`, the same as an instrument error, and not as a new status. That way the report, `exit_code` and `resume`'s refusal all already handle it. Exit 130 is the shell's convention for SIGINT. A Ctrl-C before any run exists is re-raised untouched, and a test pins that.
Learned: mini-bldc's hold run has human steps back to back, so a test that wants the next instrument step after a confirm has to loop confirm/resume. A KeyboardInterrupt that escapes a test stops the whole pytest session, so the test turns it into `pytest.fail`. SIGTERM (a killed process, a closed ssh session) still leaves a run `running`. Python has no default handler for it.
