Under Limits from the design, `npie_run.py start` refuses a stale procedure (`runner.stale_inputs`), but `confirm` and `resume` never checked again. On a change it aborts the run with the changed inputs named, and `npie_run.py` writes the report as for any aborted run. Decided: Abort rather than refuse. A refusal (exit 2, no state change) would leave the run `awaiting_human` forever, with a `.tex` but never a PDF, which works against Every run on record. Aborting ends it with the supply off and a report that says why. `confirm` aborts before it records the answer, because the step's text or limit may itself be what changed. `status` stays read-only and doesn't check.
