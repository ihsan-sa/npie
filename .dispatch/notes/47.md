# Run notes for #47

## 2026-10-15 run 1

Did: #19 is still blocked, and it was the only open goal. #37's PR line left a gap under Limits from the design: the nudge reaches only module constants, and procgen wrote numbers inline in limits. Those were the 90 % current ceiling (idle, regulating, limits-stage and spin current), -5 %/+1 % for a rail following the input, +/-5 % on the firmware's vbus reading, +/-3 % on the sense-amp offset, 0.5 +/-0.05 bridge duty, +/-2 % PWM frequency, the dead time's +1 ns, the diode's 0.5 V nominal and the Hall check's 2 edges. `derived_from` never stated the last two. I filed "No number hides inline in a limit" and did it in one step. Each number is now a procgen constant (`ILIM_CEIL_FRAC`, `FOLLOW_TOL`, `VBUS_READ_TOL`, `SENSE_REF_TOL`, `BRIDGE_DUTY`, `BRIDGE_DUTY_TOL`, `FREQ_TOL`, `DT_ROUNDUP_NS`, `DIODE_NOM_V`, `HALL_EDGES_MIN`) that `derived_from` prints. `tests/test_npie_limit_fields.py` gains an AST scan that fails on any number other than 0 and 1 (and round()'s digits) in a dict literal with a limit key, plus a test that the scan catches one. `make check`: 122 passed, 9 skipped. The nudge finds every new constant disclosed, and `UNDISCLOSED` stays empty. The goal is closed as done in this PR. I also added the Closed line for #46 and pointed the signal goal at #46.
Decided: The scan looks only at dict literals with a `nominal`/`min`/`max`/`edges_min` key, which is where every limit is written. Numbers that shape a limit from outside the dict are out of scope. That includes the supply's 0.05 A current-limit floor and 2x full load, `_open_duty`'s 0.05 and default 0.9 max duty, the over-voltage aim's 97 % of rating, and the host-link vio_v default of 3.3 V. Each of those flows into a value that `derived_from` already prints, so the nudge would pass them anyway. The wording of every limit is unchanged except the diode and Hall steps, which now state their nominal and edge count.
Learned: The nudge only proves something for steps a fixture reaches. I didn't confirm that every new constant moves a limit in some fixture variant (the sense-amp offset and the bridge-duty path may not be reached). `moved_any` is checked for the set as a whole, not per constant. The host-link vio_v falls back to 3.3 V when the block has no `operating_point.vio_v`, and its `derived_from` still says "constraints blocks[...]". That is a small trace gap no test catches.
Needs: Nothing new. Still open from earlier runs: whether "disclosed" is enough for rule constants or they should come from `bringup{}`, D0 worked out from `safety.vout_ov_v` alone, lualatex on a host that runs the checks, and the ssh config on this host that breaks `git fetch`.
